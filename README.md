# What Else Was On

A multi-agent system that watches a synthetic football match and, for every pass, asks: **what else was on?**

For each pass it works out which teammates the passer could actually see, finds better options they skipped, checks that those options would really have arrived, and turns the best moments into live commentary and a broadcast recap.

Built for the Microsoft x Premier League **Inside the Game: Developer Hackathon** (October 2026). All match data is synthetic and generated by this repo.

## How it works

| Part | What it does | Built with |
|---|---|---|
| Match generator | Simulates 22 players and the ball at 10 frames per second, plus events (passes, shots, tackles, pressure) | Python |
| Football tools | Vision cone, option value, and pass arrival for any pass | Python, exposed to the agents as tools |
| Analyst agent | Finds better visible options the passer skipped and explains them with numbers | Microsoft Foundry, Agent Framework |
| Checker agent | Re-runs the tools and rejects any claim the numbers do not support | Microsoft Foundry, Agent Framework |
| Narrator agent | Writes live commentary lines and a post-match recap | Microsoft Foundry, Agent Framework |
| Replay page | Shows the pitch, the cone, the missed options and the agents' output | Web app on Azure Container Apps |

## Status

- Day 1: project setup and a connection check to a model deployed in Microsoft Foundry.
- Days 2-3: synthetic match generator. A full 90-minute match (22 players and the ball at 10 frames per second, plus about 1,600 passes, shots, tackles, fouls and interceptions) takes about 40 seconds to generate.

- Day 4: football tools the agents call: vision cone, option value (threat), pass arrival, and `analyse_pass` / `find_missed_passes`.
- Day 5: the Analyst agent (Microsoft Agent Framework on a Foundry model) that calls those tools and returns an evidence-backed verdict as JSON.

## Football tools and the Analyst agent

```bash
python scripts/explain_pass.py --seed 1                 # biggest missed options in the match (no AI)
python scripts/explain_pass.py --seed 1 --pass 1447     # full table for one pass
python scripts/run_analyst.py --seed 1 --pass 1447      # the Analyst agent on the same pass
```

A "better option" is a teammate inside the passer's 120 degree vision cone, worth at least 1 percentage point more threat than the pass played, and reachable: a ground pass at 12.5 m/s gets there before any defender who reacts after 0.7 s and sprints at 7 m/s.

## The synthetic match generator

```bash
python scripts/generate_match.py --seed 1          # full match, about 40 s
python scripts/preview_match.py --seed 1 --minute 20
```

This writes `data/match_1_tracking.npz` (positions), `data/match_1_events.json` (teams, players, events, summary) and `data/match_1_preview.png` (a picture to check it looks like football). The same seed always gives the same match.

How it works, in short: both teams keep a formation that slides with the ball; the defending team presses the ball carrier with its nearest player and covers with the next; attackers make runs in behind. The ball carrier dribbles, then shoots or passes. Passes are chosen mostly among teammates the carrier can see, and players are a little cautious, so better options are sometimes skipped. Passes roll along the ground and can be cut out by a defender who reaches the ball's path first. All team and player names are made up.

## Quick start

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
copy .env.example .env      # Windows (use cp on macOS / Linux), then fill in your values
python scripts/smoke_test.py          # checks the model connection
python scripts/smoke_test.py --mock   # runs without Azure
```

See [docs/SETUP.md](docs/SETUP.md) for the Azure and Foundry steps.
